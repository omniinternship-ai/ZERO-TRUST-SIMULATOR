# ตั้งค่าคะแนนและสถิติ

เว็บ deploy บน Cloudflare Pages หรือ static hosting ตามเดิม ส่วน Supabase เก็บฐานข้อมูลและบัญชี ไม่ได้ใช้โฮสต์หน้า HTML นี้

1. สร้าง Supabase project แล้วรัน `schema.sql` ใน SQL Editor
2. เปิด Anonymous Sign-ins ใน Authentication สำหรับผู้เล่นไม่ต้องสมัครสมาชิก
3. ใส่ Project URL และ publishable key (หรือ anon key) ใน `js/supabase-config.js` ห้ามใช้ secret/service_role key
4. สร้างบัญชีผู้ดูแลแบบอีเมล/รหัสผ่านใน Supabase Authentication แล้วคัดลอก user UUID มารัน SQL ด้านล่าง (แทน UUID จริง)

```sql
insert into public.score_admins(user_id) values ('ADMIN-USER-UUID') on conflict do nothing;
```

5. เปิดผ่าน HTTP/HTTPS แล้วเล่นจนตอบครบ 10 ข้อ จากนั้นเปิด `statistics.html` และเข้าสู่ระบบผู้ดูแล
6. อัปโหลดไฟล์ทั้งหมด รวมหน้าใหม่และ config ไปยัง GitHub/hosting

## เกณฑ์และขอบเขต

- ปลอดภัย 1 คะแนน/ข้อ รวม 10 คะแนน; บันทึกทันทีที่ตอบครบ ไม่ว่าตัวเลือกสุดท้ายจะปลอดภัยหรือไม่
- เฉพาะสถานการณ์น้องไก่ รุ่น kai-v1; หนึ่งผลต่อบัญชีนิรนามต่อสถานการณ์ ส่งซ้ำไม่เพิ่มแถวและไม่เปลี่ยนคะแนนเดิม
- บัญชีนิรนามผูกกับเบราว์เซอร์ ไม่ใช่การยืนยันตัวบุคคล การล้างข้อมูลหรือเปลี่ยนเครื่องอาจสร้างผู้เล่นใหม่
- หากส่งไม่ได้ เก็บคำตอบรอใน localStorage และลองเมื่อเปิดหน้าใหม่/ออนไลน์/คลิกสถานะอีกครั้ง ต้องไม่ล้างข้อมูลเบราว์เซอร์ก่อนส่งสำเร็จ
- หน้าสถิติแสดงผลที่โหลดตามช่วงวันที่ พร้อมคะแนนเฉลี่ย สูงสุด จำนวนครั้ง ผู้เล่นไม่ซ้ำ การกระจายคะแนน และ CSV
- ฐานข้อมูลคำนวณคะแนนจากตัวเลือก และปิดการเขียนตารางโดยตรง ผู้เล่นอ่านคะแนนรวมไม่ได้ ผู้ดูแลเท่านั้นที่อ่านได้
- ระบบนี้ยังไม่พิสูจน์ว่าผู้เล่นเล่นจริง ผู้รู้คำตอบสามารถส่งตัวเลือกผ่าน API ได้ ไม่ควรใช้เป็นข้อสอบเดิมพันสูงโดยไม่มีระบบควบคุมเพิ่มเติม
- ไม่ส่งแชต เลขบัญชีจำลอง หรือข้อมูลส่วนบุคคลอื่นจากเกม
- ถ้าต้องการเริ่มแบบทดสอบใหม่ ให้ใช้เบราว์เซอร์ทดสอบแยก อย่าลบข้อมูลผู้เล่นจริง

## ตรวจสอบก่อนเปิดใช้งาน

ใช้ Supabase ทดสอบ: ผู้เล่นนิรนามส่งครบ 10 ข้อได้, ส่งซ้ำได้เพียงหนึ่งแถว, stage ซ้ำ/ขาดถูกปฏิเสธ, บัญชีปกติอ่านตารางไม่ได้, ผู้ดูแลอ่านได้, ออกจากระบบแล้วข้อมูลหายจากหน้า, ลอง offline แล้วกลับ online ไม่เพิ่มแถวซ้ำ
