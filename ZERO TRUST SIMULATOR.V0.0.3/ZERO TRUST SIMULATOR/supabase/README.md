# Supabase V0.0.3 player data

## ติดตั้ง
1. เปิด Supabase โปรเจกต์เดิม > SQL Editor > New query
2. วางเนื้อหาทั้งไฟล์ v003-player-data.sql แล้วกด Run
3. ตรวจ Table Editor ว่ามี v003_player_data

Migration ไม่เปลี่ยน game_results, submit_result และนโยบายของรุ่นเดิม ไม่ต้องใส่ service-role key ในเว็บ

## ข้อมูล
หนึ่งแถวต่อ auth.users.id: คะแนนภารกิจ คะแนนมินิเกม ยอดรวมที่ฐานข้อมูลบวกให้ จำนวน safest/low_safety/risky/scammed ข้อมูล stats ทั้งก้อนรวม history สถานะภารกิจ progression และคำตอบ BlockTown พร้อม revision และ updated_at

ระดับผู้เล่น/ข้อความเปรียบเทียบที่ UI คำนวณจากคะแนนสามารถคำนวณซ้ำได้ ไม่ถือเป็นข้อมูลอันดับประเทศจริง คะแนนและประวัติเก็บเป็นข้อมูลรายงานจากเครื่อง ไม่ใช่คะแนนที่ผ่านการตรวจการเล่นบนเซิร์ฟเวอร์

## API ที่เตรียมไว้
โหลด js/cloud-data.js หลัง js/auth.js ก่อนใช้งาน API (หน้า V003 ใส่ script ไว้แล้ว) และเข้าสู่ระบบ Google:

```js
const remote = await ZeroTrustCloudData.load(); // null หากยังไม่มีข้อมูล
// ให้ผู้เล่นเลือกว่าจะใช้สถิติในเครื่องหรือข้อมูล cloud ก่อนบันทึกครั้งแรก/เปลี่ยนอุปกรณ์
const saved = await ZeroTrustCloudData.save(
  ZeroTrustCloudData.snapshot(), remote?.revision ?? 0
);
// บันทึกครั้งถัดไปใช้ saved.revision เป็น expectedRevision
```

API ยังไม่บันทึกอัตโนมัติและไม่เขียนทับ localStorage ตอนโหลด ต้องเชื่อมปุ่ม/การซิงก์หลังติดตั้ง SQL และกำหนดว่าจะนำข้อมูลเดิมเข้าบัญชีใดเพื่อไม่ให้สถิติของหลายบัญชีปนกัน ข้อผิดพลาด 40001 หมายถึงข้อมูล cloud เปลี่ยนแล้ว ต้องโหลดใหม่และจัดการความขัดแย้ง ห้ามลองทับโดยใช้ revision ใหม่อัตโนมัติ

## สิทธิ์และการตรวจสอบ
RLS ให้ authenticated อ่านเฉพาะแถว auth.uid(); ไม่มี direct insert/update/delete grant เขียนผ่าน save_v003_player_data เท่านั้น RPC ตรวจโครงสร้าง ชนิดคะแนน ยอดรวม จำนวนคำตอบ และป้องกันการทับด้วย revision + transaction lock ประวัติ/เครื่องหมายรางวัล BlockTown ถูกเก็บใน stats.history จึงสำรองได้ แต่ยังไม่ใช่การรับประกันรางวัลครั้งเดียวฝั่งเซิร์ฟเวอร์

## ทดสอบหลัง Run SQL
- บัญชี A บันทึกครั้งแรกด้วย revision 0 และโหลดกลับเทียบค่า
- บัญชี B อ่านแถว A ไม่ได้; Guest ใช้ RPC ไม่ได้
- บันทึกด้วย revision เก่าต้องได้ 40001 และข้อมูลเดิมไม่เปลี่ยน
- ส่งยอดรวมไม่ตรง/คำตอบ BlockTown ไม่ใช่ 0 หรือ 1 ต้องถูกปฏิเสธ
- ตาราง legacy game_results ยังอ่าน/ใช้งานตามสิทธิ์เดิม

ยังไม่ได้รัน migration บน Supabase จริงจากงานนี้ ต้อง Run SQL และทดสอบสิทธิ์บนโปรเจกต์ก่อนเปิดใช้งาน sync

## ระบบซิงก์ที่เปิดแล้ว
cloud-sync.js โหลดข้อมูลหลังล็อกอิน ให้เลือกข้อมูลครั้งแรก ก่อนบันทึกอัตโนมัติเมื่อข้อมูลเปลี่ยน ตรวจทุก 2.5 วินาที หยุดเมื่อ revision ขัดแย้ง และมีปุ่มเชื่อมต่อใหม่ในหน้าสถิติ การเลือก Guest หยุดซิงก์ในหน้านั้น มี backup ก่อนโหลดข้อมูลออนไลน์
ทดสอบจริง: บันทึก 27 คะแนนและโหลดเทียบหลังรีเฟรชสำเร็จ ส่วนอันดับประเทศใน UI ยังเป็นข้อมูลจำลอง
