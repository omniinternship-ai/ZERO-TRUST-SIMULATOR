# SHOT Studio — ติดตั้งระบบอัปโหลดวิดีโอ

## 1. ติดตั้งฐานข้อมูลและ Storage
เปิด Supabase โปรเจกต์เดิม > SQL Editor > New query แล้ว Run supabase/short-series.sql ทั้งไฟล์
สร้าง shorts_series, shorts_episodes, shorts_admins และ bucket ส่วนตัว short-series-media ไม่แก้ข้อมูลเกมหรือคะแนน
หากมี bucket ชื่อนี้เป็น public อยู่ก่อน migration จะหยุด ให้เลือกชื่อใหม่/ตรวจ bucket เดิมก่อน ไม่เปลี่ยนสิทธิ์ไฟล์เดิมอัตโนมัติ

## 2. ให้สิทธิ์บัญชีแอดมิน
บัญชีต้องเคยล็อกอิน Google ในโปรเจกต์นี้แล้ว จากนั้นรันคำสั่งนี้ใน SQL Editor โดยแทนที่อีเมล:

```sql
insert into public.shorts_admins(user_id)
select id from auth.users where email = 'YOUR_GOOGLE_EMAIL'
on conflict do nothing;
```
ตรวจว่าบัญชีถูกเพิ่มแล้ว:

```sql
select user_id from public.shorts_admins;
```
ห้ามใส่ service_role key หรือ Google Client Secret ในไฟล์เว็บ การซ่อน URL หลังบ้านไม่ใช่การตรวจสิทธิ์ RLS และ Storage policies เป็นผู้บังคับสิทธิ์จริง

## 3. เผยแพร่และตั้งค่า Login
อัปโหลดโฟลเดอร์ Short-Series ทั้งชุดเข้า repository ZERO-TRUST-SIMULATOR แล้วเปิด:
- ผู้ชม: https://omniinternship-ai.github.io/ZERO-TRUST-SIMULATOR/Short-Series/
- หลังบ้าน: https://omniinternship-ai.github.io/ZERO-TRUST-SIMULATOR/Short-Series/admin/index.html

เพิ่ม URL หลังบ้านแบบเต็มใน Supabase > Authentication > URL Configuration > Redirect URLs
หากใช้ repository แยกหรือชื่ออื่น ให้ใช้ URL ที่เผยแพร่จริงแทน ไม่ต้องเปลี่ยน Google callback ของ Supabase
ทดสอบ Login ผ่าน HTTP/HTTPS ไม่ใช่ file:// ในเครื่องใช้ `python -m http.server 8773 --bind 127.0.0.1` ภายในโฟลเดอร์ Short-Series และเพิ่ม http://127.0.0.1:8773/admin/index.html ใน Redirect URLs

## 4. อัปโหลด
1. เข้าหลังบ้านและ Login Google บัญชีแอดมิน
2. ใส่ชื่อซีรีส์ หมวด เรื่องย่อ และโปสเตอร์ แล้วกดบันทึกซีรีส์
3. เลือกไฟล์ MP4/WebM กรอกเลขตอน ชื่อตอน รายละเอียด เลือกสถานะ แล้วกดอัปโหลดและบันทึกตอน
4. ตั้งทั้งซีรีส์และตอนเป็นเผยแพร่ เปิดหน้าผู้ชมใหม่จึงเห็นและเล่นวิดีโอจริงได้
5. แก้ตอน/นำกลับเป็นร่างได้จากรายการตอน ไม่มีปุ่มลบถาวรใน UI

ใช้ MP4 H.264 + AAC สำหรับความเข้ากันได้กว้างที่สุด แนะนำแนวตั้ง9:16 ไฟล์วิดีโอไม่เกิน50MiB และโปสเตอร์ไม่เกิน5MiB ค่าที่โปรเจกต์อนุญาตจริงอาจต่ำกว่านี้ ต้องตรวจ Storage Settings ของโปรเจกต์ หากไฟล์ใหญ่ให้บีบอัด/แบ่งตอน หรือปรับขนาดที่อนุญาตทั้งbucketและUIให้ตรงกันตามแผนที่ใช้
ไฟล์เกิน6MiB ใช้ TUS แบ่งchunk6MiB พร้อม retry อัตโนมัติ การปิดหน้า/รีโหลดอาจต้องเริ่มใหม่ ไม่มีคำสัญญาว่าจะresumeข้ามการรีโหลด

## สิทธิ์และการจัดการไฟล์
- ใครก็อ่านmetadataและสร้างลิงก์เล่นได้เฉพาะตอนเผยแพร่ในซีรีส์เผยแพร่
- ผู้ดูแลที่อยู่ใน shorts_admins เท่านั้นแก้metadataและอัปโหลด/จัดการStorageได้
- ไฟล์ทั้งหมดอยู่private bucket ผู้ชมรับลิงก์ชั่วคราวอายุ1ชั่วโมง เมื่อนำตอนกลับเป็นร่าง ลิงก์ใหม่จะไม่ออกให้ แต่ลิงก์ที่ออกไปแล้วอาจใช้ได้จนหมดอายุ
- ไฟล์อัปโหลดก่อนบันทึกmetadata ถ้าบันทึกตอนล้มเหลว UIเก็บpathไว้ให้กดซ้ำ ไม่อัปโหลดไฟล์เดิมซ้ำในหน้านั้น
- การเปลี่ยนไฟล์/บันทึกไม่สำเร็จอาจเหลือไฟล์ไม่ถูกอ้างอิงในStorage จัดการภายหลังในDashboard หลังตรวจว่าไม่ใช้งาน ไม่ลบไฟล์อัตโนมัติ
- ยังไม่ทำtranscoding,HLS/หลายความละเอียดหรือระบบเก็บประวัติรับชม การเล่นใช้native video แบบMP4/WebM

## ตรวจสอบหลังติดตั้ง
1. ไม่ล็อกอินหรือบัญชีทั่วไปต้องอัปโหลดไม่ได้ แม้เรียกAPIโดยตรง
2. บัญชีแอดมินสร้างร่าง/อัปโหลดได้ แต่หน้าผู้ชมไม่เห็นร่าง
3. เผยแพร่ซีรีส์และตอนแล้วผู้ชมเปิดวิดีโอได้
4. นำกลับเป็นร่างแล้วสร้างsigned URLใหม่ไม่ได้จากบัญชีผู้ชม
5. ตอนเลขซ้ำในเรื่องเดียวกันต้องถูกปฏิเสธ

ตรวจsyntaxและmock data flowผ่าน แต่ยังไม่ได้รันSQLหรืออัปโหลดไฟล์จริงขึ้นโปรเจกต์จากงานนี้ ต้องทดสอบRLSและการเล่นจริงหลังติดตั้ง
